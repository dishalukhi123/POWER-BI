⭐ Star Schema Design

Fact Table — FactOrderItems sits at the centre, containing measurable numeric facts (price, freight_value) and foreign keys (order_id, product_id, seller_id). One row per item sold, not per order.

Dimension Tables: DimOrders · DimCustomers · DimProducts · DimSellers · DimDate

Secondary Fact Tables (Fact Constellation / Galaxy Schema, sharing DimOrders): FactPayments · FactReviews

DimGeolocation is used purely as a lookup table for geographic enrichment.

Star vs Snowflake

FactOrderItems connects directly to DimOrders, DimProducts, DimSellers, DimDate — a Star Schema. DimOrders → DimCustomers forms a two-level chain, a Snowflake extension, since each order has one customer and customers are stored separately. FactPayments and FactReviews both connecting to DimOrders forms a Fact Constellation (Galaxy Schema).

Bi-Directional Filter Risk

The DimOrders ↔ DimCustomers relationship was temporarily set to Both cross-filter direction to observe new filter paths in both directions, then reverted to Single — bi-directional filters across multiple fact tables sharing dimensions can create ambiguous filter paths.

📅 DimDate Calendar Table

Power BI has no built-in date dimension, so a calendar table was built manually in Power Query (Home → New Source → Blank Query → Advanced Editor) spanning 2016-01-01 to 2018-12-31.

Columns (6): DateYearQuarterMonth_NumMonth_NameWeekdayYear_Quarter

  • Marked as Date Table using the Date column
  • Month_Name sorted by Month_Num so charts display Jan–Dec, not alphabetically
